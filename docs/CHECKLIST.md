# Parlor: чеклист

Порядок фиксирован. Пункт следующей фазы не начинать, пока у текущей нет отметок «готово» на том устройстве, которое реально стоит в комнате. Решение по продукту — в [PLAN.md](PLAN.md). Галочки ставятся только после прогона, не после написания кода.

Обозначения устройств в скобках:

- **GTV** — сертифицированный Google TV или Chromecast with Google TV.
- **BOX** — отдельная приставка со старым или не обновляемым WebView.
- **PH** — телефон в той же локальной сети.

## Фаза 1. Телевизор без телефона

Сборка только `tv`. Телефонного модуля нет.

- [ ] Приложение ставится на GTV из Android Studio или `adb` и появляется в лаунчере с баннером.
- [ ] Та же сборка ставится на BOX. Если BOX 32-бит, для него есть отдельный APK, Play-сборка при этом остаётся arm64.
- [ ] Адрес открывается в системном WebView. `file://` и `content://` из страницы не читаются.
- [ ] Пресет агента по умолчанию — настольный. Переключение на телефонный и «как есть» меняет строку, это видно на проверочной странице.
- [ ] Back возвращает историю и не закрывает приложение с первой же статьи. С пустой истории Back выходит.
- [ ] Курсор с пульта двигается, OK щёлкает элемент под ним, удержание OK переключает курсор и стрелки, не активируя ссылку.
- [ ] У края экрана удержание стрелки листает страницу под курсором.
- [ ] Масштаб страницы и масштаб текста меняются отдельно.
- [ ] Полноэкранный HTML5-ролик занимает экран и закрывается Back. Кнопки плеера не спрятаны под системной панелью.
- [ ] Play/pause пульта управляет звуком ролика. Уход на домашний экран не оставляет звук без способа его остановить.
- [ ] Падение рендера показывает экран ошибки и грузит последний адрес заново.
- [ ] После сна телевизора активный адрес восстанавливается.
- [ ] На старте видна версия WebView. Ниже Chrome 110 висит пометка, что движок устарел.
- [ ] В матрицу устройств записаны GTV и BOX: модель, Android, WebView, ABI, память, `devicePixelRatio`, что открылось.

Готово, когда на GTV и BOX открываются три своих обычных сайта: статья, страница с меню по наведению, страница с видео. Для каждого записано, хватило ли курсора.

## Фаза 2. Повтор шагов с телефона

Сопряжение и основной сценарий. Во время навигации смотрят в телефон.

- [ ] Телевизор виден с телефона через NSD. Если NSD молчит, соединение по IP и порту с экрана работает.
- [ ] QR одноразовый. После удачного сопряжения старый QR больше не пускает.
- [ ] Код с экрана пускает без камеры.
- [ ] Пока код не подтверждён, команды с другого устройства не действуют.
- [ ] Повторный запуск телефона соединяется сохранённым ключом и не спрашивает код.
- [ ] «Забыть телефон» на телевизоре обрывает ключ. Старый телефон больше не подключается тихо.
- [ ] Телефон показывает свою страницу. Касание по ней не является тачпадом телевизора.
- [ ] На время сессии агент телевизора совпадает с агентом телефона.
- [ ] Куки этой вкладки доезжают до телевизора по уже сопряжённому каналу. В облако они не уходят. Чужая вкладка, которую не ведут, не копируется.
- [ ] Переход по ссылке на телефоне открывает ту же ссылку на телевизоре.
- [ ] Касание кнопки повторяется поиском элемента, а не координатой экрана. Разная ширина окна не ломает этот шаг на странице с той же кнопкой.
- [ ] Play на телефоне запускает видео на телевизоре. Полный экран на телефоне разворачивает видео на телевизоре во весь экран.
- [ ] Сворачивание или закрытие приложения на телефоне ставит телефон на паузу. Телевизор продолжает с той же секунды и остаётся в полном экране.
- [ ] «Оставить в телефоне» ставит телевизор на паузу. Телефон продолжает.
- [ ] Пауза на телевизоре останавливает телевизор и не закрывает страницу на телефоне.
- [ ] Шаг, для которого на телевизоре нет элемента, не блокирует телефон. На телефоне видна короткая пометка, что этот шаг телевизор не повторил.
- [ ] Сокет не отвечает на чужой Host. Произвольный URL через телевизор как через прокси не проксируется.
- [ ] Телефон с включённым VPN получает понятный экран, а не вечную крутилку.
- [ ] Прогон на GTV и PH в обычной домашней сети, не в гостевой.

Готово, когда на телефоне открывают страницу с фильмом, нажимают Play и полный экран, не глядя в телевизор, затем сворачивают телефон и досматривают ту же секунду на GTV.

## Фаза 3. Запасной ввод

Для шага, который повтор по элементу не нашёл.

- [ ] Курсор: телефон становится тачпадом страницы, которая уже открыта на телевизоре. Касание щёлкает под указателем.
- [ ] Подсказки рисуют короткие метки на видимых ссылках и кнопках телевизора.
- [ ] Ввод метки с телефона активирует элемент. Та же метка вводится с пульта.
- [ ] Метки пересчитываются после прокрутки и после подгрузки страницы.
- [ ] Ключ сопряжения нельзя прочитать из JavaScript страницы.
- [ ] Поле на странице с React или Vue принимает текст с телефона, и то же поле на телевизоре получает событие `input`.
- [ ] Сайт, который перехватывает фокус, не забирает управление панелью Parlor навсегда. С телефона панель открывается всегда.

Готово, когда страница, где кнопка на телевизоре не совпала с телефоном, всё равно проходит курсором или меткой, а поиск на одном SPA уходит и туда, и туда.

## Фаза 4. Закладки и очередь

- [ ] Закладки синхронизируются явно, в локальной сети, между уже сопряжёнными устройствами.
- [ ] Очередь на телефоне: добавить адрес, на телевизоре открыть следующий, удалить пункт.
- [ ] История и закладки не уходят в интернет через аккаунт Parlor. Аккаунта нет.
- [ ] Куки по-прежнему копируются только у вкладки, которую ведут в режиме «С телефона».

Готово, когда закладка, сохранённая на телевизоре, видна на телефоне после синхронизации, а адрес из очереди открывается на телевизоре без пульта.

## Фаза 5. Плеер

- [ ] На обычном файле, HLS и DASH появляется действие «открыть в плеере». Само по себе видео на странице не выдёргивается.
- [ ] Плеер получает User-Agent, Referer и куки этой вкладки.
- [ ] Дорожка звука и субтитры переключаются с пульта и с телефона.
- [ ] Перемотка с телефона попадает в плеер.
- [ ] Закрытие плеера возвращает на ту же страницу.
- [ ] Поток, который без ключа не играет, не маскируется под успех. На экране причина «нужна лицензия устройства» или ошибка сети, без обещания 4K.

Готово, когда один свой ролик, который в WebView идёт с плохим звуком или не во весь экран, досматривается в своём плеере на GTV и на BOX.

## Фаза 6. Сеть, которая режет соседей

- [ ] Если TCP до телевизора не открывается, экран называет изоляцию клиентов и гостевую сеть своими словами, по адресу телевизора и результату попытки.
- [ ] BLE находит телевизор без маршрута по Wi-Fi.
- [ ] По BLE проходят адрес, назад, стрелки, щелчок и короткий текст.
- [ ] Обрыв BLE не стирает сопряжение Wi-Fi.
- [ ] HID-профиль не требуется ни на телефоне, ни на приставке.

Готово, когда команды доходят в сети, где устройства нарочно не видят друг друга, либо в чеклисте записано, что дома такой сети нет и сценарий прогнан на включённой изоляции роутера.

## Фаза 7. Гейт движка

- [ ] Матрица содержит GTV, BOX и хотя бы один сайт, который на BOX сломан.
- [ ] Для сломанного сайта записано: версия WebView, работает ли он в свежем Chrome на телефоне, можно ли обновить WebView, помогли ли агент, масштаб, курсор, плеер и читалка.
- [ ] Решение одно из трёх, записано в план датой: остаться на WebView, встроить GeckoView или открыть исследование форка Chromium.
- [ ] Форк не начат, если хотя бы один пункт гейта из плана пуст.

Готово, когда решение лежит в `docs/PLAN.md` абзацем, а не только в переписке.

## Сквозные проверки

Их прогоняют заново на той фазе, которая их затрагивает.

- [ ] Чужой телефон в той же сети не управляет телевизором.
- [ ] Сон, смена HDMI и нехватка памяти не оставляют вечный чёрный WebView.
- [ ] Сертификат с ошибкой нельзя прощелкать случайным OK. Есть отдельное подтверждение.
- [ ] Загрузка файла спрашивает место и не молчит.
- [ ] Страница не запускает внешний браузер. Новые окна остаются вкладками.
- [ ] На телефоне цели пальца не меньше 44×44 px. На телевизоре фокус виден с дивана.
- [ ] В коде нет второго канала «для отладки», который слушает команды без сопряжения.
